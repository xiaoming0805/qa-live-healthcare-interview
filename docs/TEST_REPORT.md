## 5. 结论

- 医生模块与患者模块共 **23 个接口用例全部通过**，覆盖正常分支、404 / 401 / 409 / 400 异常分支，以及两项安全回归（密码不下发、账号枚举防护）。
- 端到端验证（TC-15）确认**前端数据确实来源于 MySQL**，非前端硬编码。
- `ddl-auto=validate` 在 MySQL 5.7.44 上启动通过，说明 `specialties` 的 JSON 列与 `StringListConverter` 映射正确。

**结论：测试通过，满足 `PRD-REQ02` 与 `PRD-REQ03` 的验收标准。**
前端三个改动（首页中英文切换、医生数据改由接口供给、患者用户名密码登录）已在真实浏览器中验证通过。

## 6. 风险与说明

1. **未覆盖项**：
   - TC-01（Docker 容器健康检查）—— 测试环境无 Docker，`docker-compose.yml` 未经实际验证。
   - 注册流程的前端 UI（登录/注册模式切换、生日选择器）—— 仅通过接口验证，未在浏览器中操作。
   - 跨浏览器验证 —— 仅在 Chromium 上执行。
2. **数据库版本差异**：测试用 MySQL 5.7.44，而 `docker-compose.yml` 声明的是 8.0。两者对本次使用的特性（JSON 列、`ON UPDATE CURRENT_TIMESTAMP`、utf8mb4）行为一致，但仍建议在 8.0 上复测一次。
3. **已知设计限制**（非缺陷，详见 PRD 第 9 节）：
   - 密码明文存储与传输，仅适用于演示环境。
   - 登录态仅存于前端内存，刷新页面需重新登录。
   - 患者 id 生成采用「现有最大值 + 1」，并发注册下存在冲突可能。
4. **测试数据清理**：TC-21 创建的账号（`alice-test-*`）已在测试结束后删除，`patient` 表恢复为 5 行。
